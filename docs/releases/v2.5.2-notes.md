# v2.5.2 release notes

A fix release for Windows users whose user folder name has accented or other non-English letters, plus a live signal on the recording bar chips and two security updates. The full v2.5 notes are in [v2.5-notes.md](v2.5-notes.md).

## Fixed

- **Transcription works when your Windows user folder has accented or other non-English letters** (for example a name with ñ or ú). Before, local transcription crashed with error 0xc0000409 (issue #122). Transcription with a Groq key was hit too: the meeting went back to "Queued" and then showed Failed. Both work now. If a meeting failed this way, open it and retry it from the note after you update.

## Improved

- **Clearer errors when two engines both fail.** When one transcription engine falls back to another and both fail, the error now shows what each one reported.

## Changed

- **The "You" and "Others" chips in the recording bar show live signal.** Each is green when that source was heard in the last second or so, and grey when it is quiet. Warnings still come first. "Others" is now grey when nothing is playing.

## Security and maintenance

- **Updated libraries.** The bundled SQLite (rusqlite 0.41) and the MCP client library (rmcp 3.9.0) pick up upstream security fixes (RUSTSEC-2026-0459 and RUSTSEC-2026-0462). Your existing library needs no migration.
- **Build fixes** for the current Rust toolchain.

## Known limitation

- On Windows volumes with short (8.3) file names turned off, when your user folder name is non-English and is on a different drive than the app's data, transcription reports a clear error with the steps to fix it instead of retrying.
